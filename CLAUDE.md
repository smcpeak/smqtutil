# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`smqtutil` is a small library of Qt5 (C++17) utilities, built as
`libsmqtutil.a`. It is used mainly by the `editor` repo, which
includes it as a git submodule (the parent directory `..` is normally
the editor checkout). It depends on `smbase`, which it expects at
`../smbase` (`DEPSDIR := ..` in the `Makefile`), and links
`../smbase/obj/libsmbase.a`, so smbase must be built first.

Primary development is on Windows under Cygwin (`g++`, GNU make), and it
also builds on Linux. Build outputs (`*.o`, `*.d`, `*.moc.cc`,
`*.gen.*`, `*.exe`, `*.a`) go in the source directory next to the
sources.

## Configuration

`config.mk` is required, and the build stops with an error if it is
missing. Copy `config.mk.template` and set `QT5INCLUDE`, `QT5LIB`, and
`QT5BIN`. `qtvars.mk` checks those paths and sets `QT_CCFLAGS` /
`QT_LDFLAGS` plus the `moc` and `rcc` pattern rules. The parent
`editor` repo includes `qtvars.mk` too. Note that `-DQT_NO_KEYWORDS` is
always on: use `Q_EMIT`, `Q_SIGNALS`, `Q_SLOTS`, and `Q_FOREACH`, never
`emit`, `signals`, `slots`, or `foreach`.

## Build and test commands

- `make` builds the library, `unit-tests.exe`, and `gui-tests.exe`.
- `make check` runs `./unit-tests.exe` and `./gui-tests.exe -all -nogui`
  (non-interactive), each under a 10-second `timeout`.
- `make gui-check` runs the interactive GUI tests (`gui-tests.exe -all`).
  Each one pops up a window that the user must close. Don't run it
  unless asked to.
- `make clean`

Running one module's tests:

- `./unit-tests.exe <module>`, such as `./unit-tests.exe sync_wait`
  (module name with underscores).
- `./gui-tests.exe [-nogui] <module>`. With no arguments it prints
  usage and the module names.

### Adding tests

- Unit test: write `foo-test.cc` defining `void test_foo()` (no
  arguments). Add `RUN_TEST(foo)` to `unit-tests.cc` and `foo-test.o` to
  `UNIT_TEST_OBJS`. Use the `smbase/sm-test.h` macros (`EXPECT_EQ`,
  etc.). `unit-tests.exe` creates only a `QCoreApplication`, so these
  tests can't need a display.
- GUI test: write `foo-gui-test.cc` defining
  `int gui_test_foo(QApplication &app, bool nogui)`, which returns an
  exit code. When `nogui` is set, it runs only the non-interactive
  checks. Otherwise it shows a window and returns `app.exec()`.
  `TestMainWindow` (`test-main-window.h`) is a convenient main window
  for these. Register the test with `RUN_TEST(foo)` in `gui-tests.cc`
  and add the `.o` to `GUI_TEST_OBJS`.

Prefer unit tests where possible, and keep GUI tests for things that
really need a live widget.

## Structure

- `qtutil` covers QtCore-only helpers (string/`QString` conversion, key
  and event names, `operator<<` for Qt types, `disconnectSignals`, a Qt
  message handler). `qtguiutil` holds helpers that need QtGui or
  QtWidgets (clipboard, window geometry, and so on). Keep this split so
  QtCore-only clients don't pull in GUI dependencies. `keys.incl` is an
  X-macro list of `Qt::Key` values, included more than once by
  `qtutil.cc`.
- `qstringb.h` provides the `qstringb(...)` macro (like smbase
  `stringb`, but it yields a `QString`).
- `gdvalue-qt` converts between smbase `GDValue` and Qt types
  (`toGDValue`, `GDVPTo<T>`).
- `qtbdffont` draws text with BDF bitmap fonts (parsed by
  `smbase/bdffont`) without using the window system's font rendering.
  The fonts in `fonts/*.bdf` are compiled in as string literals
  (`*.bdf.gen.{cc,h}`, generated by `smbase/file-to-strlit.py`, with
  symbol `bdfFontData_<name>`). To add a font, add it to `BDFGENSRC`.
- `sm-table-widget` (`SMTableWidget`, a `QTableWidget` subclass) uses
  `col-width-rules` (`ColumnWidthRules`, a widget-independent
  column-width constraint solver that is unit-tested on its own). Its
  scrolling design is in `doc/sm-table-widget-scroll.ded.png`.
- `sync-wait` has the `SynchronousWaiter` interface, with
  `GUISynchronousWaiter` (which shows a delayed cancelable modal dialog
  while it services the event loop) and `MockSynchronousWaiter` for
  tests.
- Smaller modules: `sm-line-edit`, `qhboxframe`, `timer-event-loop`, and
  `silent-mbox-filter` (stops message boxes from beeping, for tests).

## Conventions

- Each file starts with a `// filename` line and a one-line
  description, and ends with `// EOF`. Each `#include` has a trailing
  comment naming what it provides. Includes of smbase and smqtutil
  headers use the directory prefix (`"smbase/str.h"`,
  `"smqtutil/qtutil.h"`), since only `-I..` is passed. Headers often
  have a `foo-fwd.h` with forward declarations for other headers to use.
- New `.o` files have to be added by hand to `OBJS` /
  `UNIT_TEST_OBJS` / `GUI_TEST_OBJS` in the `Makefile`. Classes that
  use `Q_OBJECT` also need `foo.moc.o` listed.
- **Signals and destructors:** if a constructor calls
  `QObject::connect`, its destructor must explicitly call
  `disconnectSignals(sender, receiver)` (from `qtutil.h`) for each
  connected pair, rather than relying on `~QObject`. See
  `doc/signals-and-dtors.txt` for why.
- Commit messages have the form `<module>: <Change>.`, or
  `Add module: <name>.` for a new module.
